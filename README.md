# SMPLanner — VMOne Social Media Dashboard

A static HTML/JS dashboard for planning, tracking, and analyzing social media content for the VMOne music project.

**Live site:** https://rbrambley.github.io/SMPLanner/

## What it does

- **Today / This Week:** Shows the current or next scheduled post with copy-paste packages for YouTube Shorts, YouTube Lyric Videos, Instagram Reels, Facebook Reels, and Threads.
- **Song Library:** Searchable, collapsible list of all songs with platform-specific text packages.
- **New Song:** Parse AI-generated JSON to quickly add a song, or fill in the form manually. Pick the post date, platforms, YouTube video IDs, and the dashboard auto-suggests the next open slot.
- **Release Plan:** Generate copy-paste AI prompts for singles, EPs, and albums.
- **Releases:** View all planned releases and their progress.
- **Tasks:** Per-release checklists for each song plus brand/admin tasks.
- **Analytics:** YouTube views, likes, comments, watch time, and subscriber gain for every channel video (updated daily by GitHub Actions).

## Data files

- `content.json` — songs, schedule, releases, checklist templates, tasks, and the latest YouTube stats.
- `analytics.json` — daily time-series YouTube analytics (generated by the GitHub Actions workflow).

## Release planning

1. Go to the **New Song** tab, fill in the song, choose the post date (or click **Suggest next open date**), pick platforms, and set the YouTube Short/Lyric IDs if they already exist.
2. Choose **New single release** to create a release and a checklist in one click.
3. Click **Generate Song JSON**, review the output, then click **Add to content.json and save**.
4. The new song appears in **Song Library**, the schedule in **This Week**, and the checklist in **Tasks**.

`content.json` stores the checklist templates under `templates` and planned releases under `releases`. The default templates are `single-release` and `ep-release`.

## YouTube Analytics sync

A daily GitHub Actions workflow fetches YouTube Data API v3 and YouTube Analytics API v2 data and commits the results to `analytics.json` and `content.json`.

### Setup

1. **Google Cloud project**
   - Go to https://console.cloud.google.com/ and create a new project.
   - Enable the **YouTube Data API v3** and **YouTube Analytics API v2**.
   - Configure the OAuth consent screen (External) and add these scopes:
     - `https://www.googleapis.com/auth/youtube.readonly`
     - `https://www.googleapis.com/auth/yt-analytics.readonly`
   - Create an **OAuth 2.0 Desktop app** credential and download `client_secret.json`.

2. **Get a refresh token**
   ```bash
   pip install -r scripts/requirements.txt
   python scripts/get_refresh_token.py client_secret.json
   ```
   Copy the printed `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_REFRESH_TOKEN`.

3. **Add GitHub secrets**
   In the `SMPLanner` repo, go to **Settings → Secrets and variables → Actions** and add:
   - `GOOGLE_CLIENT_ID`
   - `GOOGLE_CLIENT_SECRET`
   - `GOOGLE_REFRESH_TOKEN`
   - `YOUTUBE_CHANNEL_ID` (optional; the workflow uses the authenticated user's channel if not set)

4. **Trigger the workflow**
   - Go to **Actions → YouTube Analytics Sync** and click **Run workflow**.
   - The first run may take a few minutes while it scans all uploaded videos.

### Video-to-song matching

The workflow matches YouTube videos to songs in `content.json` in this order:

1. `links.youtube_short_id` or `links.youtube_lyric_id` if set.
2. Video title contains the song title (or vice versa).

To get the most accurate stats, add the YouTube video IDs to each song's `links.youtube_short_id` and `links.youtube_lyric_id` fields in `content.json`.

### Notes

- YouTube Analytics data is usually available 1–2 days after the activity occurs.
- The workflow fetches the last 30 days of data each run.
- Keep `client_secret.json` and `credentials.json` out of Git; they are ignored by `.gitignore`.
- The refresh token can expire if Google access is revoked. Re-run `get_refresh_token.py` to generate a new one.
